# 공통 수업 엔진 테스트 안내

[테스트 사이트 열기](https://chemtea.github.io/Curr.2022-Science-2-Server-Test/)

수업마다 바뀌는 본문·실험·문항·피드백을 등록하면, 단계 이동·형성평가·제출·포인트는 공통 엔진이 처리하는 구조입니다. 새 차시를 추가할 때 공통 JavaScript나 index를 수정할 필요가 없습니다.

## 먼저 새 차시로 확인하세요

테스트 차시는 **「새 차시 테스트 · 거울의 반사각 탐구」**입니다. 단원 ID는 `unit_demo`, 수업 ID는 `demo_reflection_l1`입니다. 관리자 모드의 **자료 관리**에서 이 제목을 찾아 열어 보세요.

교사 미리보기는 내용과 동작을 확인하는 용도이며 실제 학생 점수·포인트를 지급하지 않습니다. 실제 기록까지 확인하려면 학생에게 공개한 뒤, 별도 브라우저 프로필에서 승인된 테스트 학생 계정으로 로그인하세요. 수업·단원·형성평가 단계가 잠겨 있으면 관리자 자료 관리에서 해당 범위도 열어야 합니다.

1. 1~3단계의 본문·실험과 단계 이름이 표시되는지 확인합니다.
2. 형성평가에서 답을 하나 선택합니다. 선택이 고정되고 해당 답의 정오답 피드백이 바로 나와야 합니다. 새로고침해도 최초 선택은 유지되어야 합니다.
3. 오답 안내의 **관련 단계 복습**을 눌러 연결된 학습 단계로 이동합니다. 다시 형성평가로 돌아와도 이미 고른 답은 바뀌지 않아야 합니다.
4. 모든 문항에 답한 뒤 최종 제출합니다. 점수·지급 포인트를 확인하고 index의 포인트 창에서 잔액과 지급 기록을 확인합니다.
5. 제출 후 다른 답을 눌러 복습합니다. 피드백은 볼 수 있지만 최초 점수와 포인트는 바뀌지 않아야 합니다. 제출 재시도·새로고침으로 같은 포인트가 다시 지급되어서도 안 됩니다.

기존 서버 지급 규칙은 그대로 사용합니다. **최초 제출 1회만** 지급하며, 문항 선택만으로 지급하지 않습니다.

| 4문항 점수 | 4/4 | 3/4 | 2/4 | 1/4 | 0/4 |
|---|---:|---:|---:|---:|---:|
| 지급 포인트 | 20P | 15P | 10P | 5P | 1P |

같은 학생의 기존 차시 제출·잔액·원장을 이어서 사용합니다. 내용 버전을 바꾸어도 같은 수업 ID의 최초 지급 기록은 유지됩니다. 이미 제출한 계정으로 테스트하면 새 포인트가 지급되지 않는 것이 정상입니다.

## 내 수업을 추가하는 순서

**index → 관리자 모드 → 자료 관리 → 수업자료 가져오기**에서 학습 내용 ZIP 또는 단일 JSON을 선택합니다. ZIP에 여러 차시가 있으면 가져올 차시를 선택하고, 제목·단원·수업 ID·문항을 확인한 뒤 **교사 전용으로 새 차시 등록**을 누릅니다. 등록한 수업을 열어 확인하고 마지막에 자료 목록의 **학생 공개**를 선택합니다.

지원하는 파일은 앞서 정리한 학습 내용 양식입니다. 기존 소단원 HTML 모음이나 `lesson.json` 하나만 올리는 방식은 아니며, 단일 JSON에는 본문·실험·문항 파일 내용까지 포함되어야 합니다. PDF는 자료 관리의 학습지 업로드를 사용합니다.

새 수업은 기존 수업과 다른 고유 ID를 사용하세요. 기존 수업의 내용을 고칠 때는 새 차시 등록 대신 **본문·버전 관리**를 사용합니다. 교사용 원본에는 정답·해설이 들어 있으므로 학생에게 공유하거나 공개 GitHub 저장소에 올리지 마세요. 별도로 제공되는 비공개 원본을 가져오면 서버가 학생용 문항과 교사용 정답을 분리해 보관합니다.

## 현재 확인 범위

이 안내서 작성 시점에는 기존 15차시의 학습 내용 양식 변환, SQL 지급 규칙·연결 구조와 VM 기반 검사를 확인했습니다. 실제 배포·HTTP 통합 검증은 진행 중이며, 완료 여부는 최종 배포 검증 기록을 기준으로 확인해야 합니다. 이 문서 자체가 모든 기능의 실기기 검증 완료를 뜻하지 않습니다.

현재 사용 중인 14차시는 새 공통 형식으로 이관할 계획입니다. 이미 보관된 `u3_l1`은 보관 상태와 사용자 변경을 지키기 위해 이번 일괄 이관에서 그대로 둡니다.

학습지의 수업 잠금과 독립된 열기 흐름, 누락 PDF 4개, 수행평가의 전체 제출·수합 흐름, 실제 태블릿 필기·마이크·3D 기기 검증, 기존 포인트 API의 계정 정지·동의 검사 통일은 별도 확인이 남아 있습니다. 이번 공통 엔진 테스트를 기존 플랫폼 전체의 완전한 이관으로 보지는 마세요.
