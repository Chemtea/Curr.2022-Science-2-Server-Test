# 과학 플랫폼 서버 구조 테스트

지정 대상은 **Chemtea-lab / science-platform-test / `rerykeslgwhamreoskgx`**이며 Free 조직의 서울 리전 프로젝트입니다. 운영 프로젝트와 데이터는 수정하지 않습니다.

## 현재 상태 — 2026-09-13

코드 구현과 로컬 검사는 완료했지만 **Supabase 실행 환경은 아직 설치되지 않았습니다.** 프로젝트 상태가 `INACTIVE`이고, 재개 요청은 `Project not found`, 함수 배포는 `Cannot retrieve service ... INACTIVE`로 거절됐습니다. DB 읽기도 연결 시간 초과가 발생했습니다. 이 상태에서 SQL 설치·자료 등록·실제 로그인/업로드가 완료되었다고 간주하면 안 됩니다.

index의 **업로드 화면 미리보기**는 로그인 없이 양식을 살펴보는 기능이며 저장은 비활성화됩니다. 실제 자료 목록은 서버 응답을 사용하고, 연결 실패 시 명확한 오류를 표시합니다.

## 구현한 기능

- 제공된 최신 index와 소단원 15개를 기준으로 구성했습니다. 3단원 4차시는 임의로 만들지 않았습니다.
- 로그인, 단계 잠금, 퀴즈 제출, PDF 학습지 필기 기능은 `assets/lesson-*.js/css`의 공통 코드로 분리했습니다. 차시 HTML에는 수업 내용과 고유 시뮬레이션만 남습니다.
- index의 **교사 자료 관리**에서 등록·수정·공개·보관하면 서버 자료 목록에 반영됩니다. 일상적인 수업 추가는 GitHub 수정이나 재배포가 필요 없습니다.
- 새 공통 수업은 `science-lesson/v1` JSON 수업팩으로 등록합니다. 양식은 업로드 화면에서 받을 수 있습니다. 수업 내용만 바꿔 공통 화면을 사용합니다.
- PDF는 학습지로 등록하고 차시 ID를 연결합니다. 학습지함과 해당 차시의 PDF 패널에서 서버에 등록된 자료를 받습니다. 기존 PDF 2개는 비공개 초기 등록 자료로 별도 보존했습니다.
- 기존 단독 HTML도 등록할 수 있습니다. 부모 페이지의 로그인 정보에 접근할 수 없는 별도 화면에서 실행하며, 외부 통신은 막습니다. 임의의 HTML을 공통 수업 구조로 자동 변환하거나 새로운 3D 실험을 자동 생성하는 기능은 포함하지 않습니다.

## 자료 보호

- `content-api`가 기존 `stu_` / `adm_` 세션의 해시·만료·계정 상태와 실제 권한을 서버에서 확인합니다. 학생이 브라우저의 역할 값을 바꿔도 업로드/교사 답안 접근을 허용하지 않습니다.
- 자료 테이블은 RLS를 켜고 익명/일반 DB 접근 권한을 제거합니다. PDF Storage bucket도 비공개입니다. 이 설정은 **SQL 적용 후** 효력을 가집니다.
- 모범답안은 교사 전용입니다. 수행평가는 기본 비공개이며, 학생 공개 설정과 평가장·단원·차시 잠금이 모두 허용되어야 전달합니다. 보호 HTML은 스크립트도 실행하지 않습니다.
- 15차시의 60문항 정답·해설은 공개 코드에서 분리했습니다. 학생의 실제 선택 번호로 서버가 채점하며, 기존 클라이언트 점수 제출 API는 교체 배포 후 차단됩니다.
- 이번 테스트의 새 퀴즈는 제출·채점만 기록하며 **포인트를 지급하지 않습니다.** 기존 테스트 DB의 포인트 원자적 지급 규칙 확인 후 연결해야 합니다. 기존 교사 제출 대시보드에도 신규 기록 조회 연결 작업이 남습니다.
- 테스트 세션·필기는 프로젝트 전용 저장 키를 사용합니다. 같은 GitHub Pages 도메인의 운영 로그인 정보를 가져오지 않습니다.

현재 브랜치의 기존 평가 4개 주소는 내용 없는 보호 안내로 대체했습니다. **과거 Git 커밋에 공개됐던 답안은 이 변경만으로 지워지지 않습니다.** 이미 배포된 과거 답안의 기밀성을 되돌렸다고 볼 수 없습니다. 기존 계정의 최초 비밀번호 등록에 초대/활성화 코드를 요구하는 개선도 이번에 적용하지 않았습니다.

## 프로젝트 재개 후 설치 순서

1. 정확한 Free 프로젝트를 재개하고 연결 권한을 확인합니다. 다른 조직의 비슷한 이름 프로젝트로 대체하지 않습니다.
2. 기존 테이블/권한/계정 상태의 **구조만** 확인하고 백업합니다. 실제 학생 답안·암호 해시·세션 목록을 출력하지 않습니다.
3. `supabase/schema/content-platform.sql`, `supabase/schema/lock-patches.sql`을 검토해 해당 테스트 DB에 적용합니다. DB가 중지되어 있으므로 현재 파일은 미실행 설치안입니다.
4. `content-api`, `lock-realtime-api`, `submission-api`를 배포합니다. 이 함수들은 자체 세션 인증을 하므로 Supabase JWT 검사는 `false`로 설정합니다. 서버 기본 `SUPABASE_SERVICE_ROLE_KEY`는 브라우저나 GitHub에 넣지 않습니다.
5. `content-api`의 `health`가 정확한 프로젝트와 `databaseReady:true`를 반환하는지 확인합니다. 전용 테스트 관리자 세션으로 별도 보관한 초기 수업·학습지·평가 보관본을 등록합니다. `tools/import_content.py`는 기존 ID를 덮어쓰지 않는 초기 등록 보조 도구입니다.
6. 교사 자료 관리에서 공개 여부를 정합니다. 내장 차시는 기존 단원/차시/단계 잠금도 함께 설정해야 합니다. 학습지와 보호 자료는 처음에는 비공개입니다.
7. 테스트 학생으로 목록→수업→퀴즈→학습지 경로, 교사 업로드 후 자동 목록 반영, 학생의 답안 직접 조회 거절, 만료 세션 거절을 확인합니다. 실제 DB RLS/Storage 직접 접근과 보안 진단도 확인합니다.

관리자 키나 학생 계정을 운영에서 복사하지 않습니다. 일반 브라우저에 Supabase 서비스 키를 입력하는 기능도 없습니다.

## 검사와 파일 구성

`node --test tests/*.test.mjs`로 API/권한·세션 분리·잠금 요청 검사를 실행합니다. 이는 독립 모의 저장소를 사용한 코드 검사이며, 실제 Supabase 통합 검사와 구분해야 합니다. 변환한 15페이지의 JavaScript 문법과 파일 참조도 확인했습니다. 태블릿 필기, 실제 마이크, 3D 렌더링은 실제 기기 검증이 남습니다.

- `index.html`, `assets/content-*`: 자료 관리와 자료 조회
- `lesson.html`, `assets/lesson-*`: 공통 수업 실행 기능과 기존 실험 모듈
- `platform-config.js`: 정확한 테스트 서버 주소와 저장 키 분리
- `supabase/functions/`: 서버 함수
- `supabase/schema/`: 재개 후 적용할 SQL
- `tools/build_lessons.py`: 제공된 HTML에서 공통 기능과 차시 내용을 추출하는 이관 도구
- `tools/prepare_test_site.py`: 추출 후 브라우저 저장 키 분리
- `tools/import_content.py`: 비공개 초기 자료 등록 보조 도구

비공개 정답 seed, 평가 원문, PDF, 실제 인증 키는 이 저장소에 커밋하지 않습니다. 기존 최신 index가 호출하는 일부 관리 API는 오래된 테스트 서버에 없을 수 있으며, 재개 후 필요한 기능별로 확인·이관해야 합니다.
